C6500XK profile builder

Fill in the values that your own unit reports. This page writes a profile and the matching environment commands. It fills model constants that are already known. It does not invent per-unit values.

Runs entirely in this tab, no network requests

Read this before you change a VLAN

If the Internet VLAN does not match the router, the link stays up. The PON reaches O5.1. DHCP then fails and you have no internet.

  • Keep Fix VLANs at 1.
  • Set Internet VLAN to 0 for an untagged WAN.
  • Use one number for Services VLAN. Do not enter a range or a colon.
  • Do not save these fields in the LuCI form. The form submits every field and can overwrite your values. Use the commands from this page.
  • Reboot after you apply the commands. Then check the WAN lease.

If you lose internet, connect to 192.168.11.1. Run fw_printenv | grep 8311_. Compare 8311_internet_vlan with the router WAN setting. Correct the value and reboot.

    What this page does and does not do
    
    
      
      
    • It rewrites three kinds of value in a profile whose other rows are model constants: the vendor ID, the equipment ID, and the instance numbers that encode the PON slot.
      • 
      
    • It writes the hardware version into ONU-G, and into the circuit-pack rows when Sync is on.
      • 
      
    • It leaves the ONU-G serial at 00000000 on purpose. The daemon derives the serial from the PLOAM serial, and a literal here conflicts with your own registration.
      • 
      
    • It writes the same values as 8311_ environment commands. The boot script copies them out of the environment and overwrites the profile rows. The helper writes both environment copies.
      • 
      
    • It does not generate service rates or GEM identifiers. The OLT owns those values and replays them at runtime.
      • 
      
    • Nothing you type is stored, transmitted or logged. There is no analytics, no cookie, no storage call and no request after the page loads. The policy in the page header blocks connections outright.
      • 
      
    • The result mirrors one model, validated on one line against one OLT. It is not a guarantee of provisioning, and it is not a substitute for reading your own unit first.
